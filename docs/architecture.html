Architecture Reference

Factory Inventory Management System

A demo full-stack analytics dashboard. A Vue 3 SPA renders six read-only views over a FastAPI service that filters JSON fixtures held in memory. There is no database, no authentication, and no write path — every request is a GET against data loaded once at process start.

Vue 3.4 + Vite 5 FastAPI + Pydantic v2 14 GET endpoints 7 JSON fixtures ~8.5k lines client no database

System Architecture

Four tiers, one process each. The browser holds all UI state; the server is stateless between requests and never mutates its fixtures.

Data Flow — a filter change, end to end

The filter bar is the spine of the app. It is not wired with props or provide/inject: useFilters.js declares its refs at module scope, so every importer shares one instance and each view watches it independently.

  1. User picks a valueA <select> in FilterBar.vue v-models straight onto the shared ref — no emit.
  2. Watchers fireEach mounted view runs its own watch([...]) on the refs it cares about and re-calls its loader.
  3. Filters mappedgetCurrentFilters() renames Location → warehouse, Period → month, omitting 'all'.
  4. Request issuedapi.js builds the query string; axios GETs port 8001.
  5. Server filtersapply_filters() then filter_by_month() narrow the in-memory list by comprehension.
  6. Response validatedPydantic serialises list routes; aggregate routes return plain dicts unvalidated.
  7. Refs updatedThe view assigns raw data into refs — allOrders, inventoryItems.
  8. Computeds re-deriveTotals, groupings and client-side cross-filtering recompute; the DOM patches.

Where filtering actually happens

Filtering is deliberately split. The server narrows by warehouse, category, status and month; the client does the cross-entity work the API cannot — Dashboard and Demand build a Set of SKUs from the filtered inventory response and use it to filter backlog and forecasts locally, since /api/backlog and /api/demand accept no parameters.

Notes for New Contributors

Conventions worth knowing, and loose ends found while mapping the codebase.

  • Raw data in refs, derived data in computeds The house pattern. Views store the API response verbatim (allOrders, inventoryItems) and derive every total, grouping and chart input in a computed. Follow it — several views depend on re-deriving when the shared filter refs change.
  • Restart the backend after editing JSON mock_data.py loads at import, so fixtures are frozen for the life of the process. No hot reload on the data layer.
  • The client calls five endpoints the server does not implement /api/tasks (GET, POST, DELETE, PATCH) and /api/purchase-orders are defined in api.js and called from App.vue, but no matching route exists in main.py — those requests 404. The PurchaseOrder and CreatePurchaseOrderRequest Pydantic models are the unfinished server half.
  • Warehouse filtering is case-sensitive, category filtering is not apply_filters() compares warehouse with == but lowercases category and status. ?warehouse=tokyo returns nothing; ?category=sensors works.
  • Month filtering is substring matching filter_by_month() tests month in order_date against an ISO string, and QUARTER_MAP is hardcoded to 2025. Non-2025 data silently drops out of the quarterly report.
  • Reports.vue is the architectural outlier Options API rather than Composition API, direct axios rather than api.js, no i18n, and no connection to useFilters — the filter bar renders above it but does nothing. Treat it as the exception, not the template.
  • Dead code to be aware of Backlog.vue is unrouted and unimported (its content is duplicated inside Dashboard). Dashboard.vue references a <PurchaseOrderModal> that does not exist on disk. generate_data.py is stale relative to the committed fixtures.
  • Design system Slate palette (#0f172a, #64748b, #e2e8f0), green/blue/yellow/red status badges, custom SVG and CSS-grid charts, and no emojis in the UI. Global classes live unscoped in App.vue.
